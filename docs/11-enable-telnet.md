# 11 · 开启光猫 Telnet：所需材料与完整方法

> 前面所有章节都假设 telnet 已经能连上。但很多运营商定制光猫出厂时 **23 端口是关闭的**，第一步就得先把 telnet 打开。这一章讲清楚需要什么、以及按什么顺序试。
>
> 全文脱敏：不含任何设备的 SN、MAC、LOID、账号或真实口令；文中出现的默认凭据都是厂商公开通用值，不是本次设备专属信息。

---

## 0. 先判断你属于哪种情况

用一根网线把电脑直连光猫 LAN 口，电脑设同网段静态地址，然后测端口：

```sh
nc -z -G 2 <光猫管理IP> 23 && echo "telnet 已开" || echo "telnet 关闭"
```

- **已开** → 直接看 [02-prepare.md](02-prepare.md)，用 `root` + telnet 口令登录即可，本章不用看。
- **关闭** → 按下面顺序做。

---

## 1. 所需材料

| 类别 | 具体 | 为什么必需 |
|---|---|---|
| 电脑 + 网卡 | 能设静态 IP 的 USB / 独立网卡 | 光猫管理口通常不与主网同段，必须直连 |
| 网线 | 一根 | 电脑 ↔ 光猫 LAN 口 |
| 牙签 / 卡针 | 一根 | 长按 RESET 孔（关键，见方法 B） |
| 工具脚本 | `tools/zte_factory.py` | 走工厂模式开临时 telnet（本章提供） |
| Python 3 | 标准库即可 | 运行工具 |
| （可选）手机 | 连光猫 WiFi | 重启后确认设备上线 |
| （兜底）付费软解 | 见方法 C | 前两种都失败时 |

**物理条件**：能随时拔插光纤与电源、能看到指示灯、知道 RESET 孔位置。

> ⚠️ **重要：开 telnet 期间务必拔掉光纤。** 光猫一插纤就可能向运营商 ACS/ITMS 注册，随机化超级口令，把factory模式的默认凭据冲掉。拔纤操作是在"设备未注册"的干净状态下做，成功率最高。

---

## 2. 方法 A：已知超级口令，Web 直接开

如果你能从运营商或旧设备记录里拿到超级管理员口令：

1. 用超级管理员登录光猫 Web 管理页
2. 找「高级设置 / 系统管理 / Telnet」类开关（不同固件位置不同），打开
3. 立即测 23 端口，用 telnet 口令登录确认

大部分 2024 年后的运营商定制机**拿不到超密**（口令由后台随机生成并定期轮换），直接进方法 B。

---

## 3. 方法 B：工厂模式开临时 telnet（主力方法）

中兴 `.gch` 框架的光猫有一个 **webFac 工厂模式接口**。走通握手后可以给设备下发「开启 telnet」指令，无需超级口令。

### 3.1 关键前提：rreset 标志位

新版固件有个隐藏标志位 `rreset`（TagParam 2185）。它决定工厂模式认证用哪套凭据：

- `rreset = 0` → 用各省定制的超密，**本地算不出来**
- `rreset = 1` → 切换到通用工厂凭据 `factorymode / nE%jA@5b`，**不需要超密**

**怎么把 rreset 置 1：光猫保持通电、不插光纤，用牙签按住 RESET 孔 20~25 秒，再松手等重启。**

> 这是最容易出错的一步：很多人按 8~10 秒（那是常规恢复出厂的时长），**根本不会置位 rreset**，于是后面工厂凭据全部认证失败，误以为"软件路线走不通"。按够 20 秒是分水岭。

### 3.2 端口与工具

- **新固件的工厂接口在 80 端口，不是 8080**（8080 上是僵尸空响应，容易误导）。先用工具探测，80 不通再试 8080。
- 工具：`tools/zte_factory.py`（本仓库提供，是开源项目 `zteOnu` 协议的 Python 复刻）

```sh
# 拔纤、长按 reset 20-25 秒、等重启完成后：
python3 tools/zte_factory.py -i <光猫管理IP> -p 80 -u factorymode -w '<工厂口令>' -m <本机网卡MAC>
```

工具会自动完成握手（含本机 MAC 载荷校验——光猫从 ARP 层核对你的真实网卡 MAC，MAC 填错就过不了），成功后返回临时 telnet 账号/口令。

### 3.3 立刻验证并固化

拿到临时 telnet 后，**趁重启还在、凭据未失效**，立刻登录并把 telnet 固化（见第 4 节）。

---

## 4. 固化为永久 telnet

临时 telnet 重启后会消失。固化步骤：

```sh
# 登录后执行
sendcmd 1 DB set TelnetCfg 0 Lan_Enable 1
sendcmd 1 DB set TelnetCfg 0 Wan_Enable 1
sendcmd 1 DB set TelnetCfg 0 Max_Con_Num 2
sendcmd 1 DB save
```

两个坑：

1. **`sendcmd 1 DB p TelnetCfg` 读回的是缓存视图**，可能仍显示旧值，不代表写入失败。判断成功的标准是「重启后能不能用 telnet 口令登录」。
2. **`reboot` 命令是软重启，可能不落盘。** 固化后请**物理断电**：拔电源等 10 秒再插回。这是多次踩坑后确认的唯一可靠方式。

验证：

```sh
nc -z -G 2 <光猫管理IP> 23 && echo "端口已开"
telnet <光猫管理IP>     # 用 telnet 用户名/口令登录，id 应为 uid=0
```

## 5. 方法 C：兜底 —— 付费软解

如果方法 B 的工厂凭据仍然认证失败（部分 2025 年后的批次被彻底锁死），剩下的是运营商官方工具路线：

- 闲鱼搜「G7615AV5 开 telnet」等关键词，普遍 10~30 元，按卖家指导远程用中兴授权工具（TelnetONU）开临时 telnet
- 操作同样要求：**全程拔掉光纤**、电脑直连光猫 LAN 口
- 临时 telnet 拿到后，立刻按第 4 节固化

这一步是纯经济成本，不再需要你理解协议细节。

---

## 6. 常见失败原因速查

| 现象 | 原因 | 处理 |
|---|---|---|
| 工厂凭据全 401 | RESET 只按了 8~10 秒，rreset 没置 1 | 拔纤、长按 20~25 秒 |
| 工厂接口无响应 | 端口用错，试了 8080 | 改 80 端口 |
| 握手过了但认证不过 | 本机 MAC 载荷不匹配 | 用 `--mac` 显式指定直连网卡真实 MAC |
| 固化命令"失败" | `p` 读回缓存假象 | 不看 `p`，直接物理断电后登录验证 |
| 重启后 telnet 又没了 | 用 `reboot` 软重启，没落盘 | 物理断电重启 |
| 开完 telnet 又失效 | 插了光纤，ITMS 重新下发配置 | 全程拔纤操作，做完再插 |

## 7. 安全与边界

- **只对自有设备操作**，不要对运营商线路做身份克隆、绕过计费等事；本章只讲开启自己设备的管理通道。
- telnet 是明文协议，固化后建议改掉默认口令，且不要暴露到公网（确认 `Wan_Enable` 只在需要时打开）。
- 所有身份信息（SN / MAC / LOID / 口令）只写本地笔记，公开发布前按 [09-publish-checklist.md](09-publish-checklist.md) 扫描。
